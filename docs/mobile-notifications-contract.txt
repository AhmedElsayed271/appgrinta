شرح إشعارات Grinta لفريق الموبايل
==================================

في نوعين إشعارات عندنا، وكل واحد ليه مسار مختلف:

1) Push Notification (Firebase Cloud Messaging - FCM)
   - بتوصل للجهاز حتى لو التطبيق مقفول.
   - بتحتوي على: title, body, image, و data (مفاتيح إضافية للتوجيه).

2) In-App Bell (إشعارات جوه التطبيق - مخزنة في الداتابيز)
   - بتظهر في جرس الإشعارات داخل التطبيق.
   - بتتقرا من الـ API، وكل إشعار ليه نوع (type).


==================================================
1) شكل إشعار الجرس (In-App Bell)
==================================================

الـ API (محمي بالتوكن بتاع العميل)
----------------------------------
GET    /api/v1/notifications                 -> لستة الإشعارات (Pagination)
GET    /api/v1/notifications/unread-count    -> عدد الإشعارات غير المقروءة
POST   /api/v1/notifications/read             -> تعليم إشعار كمقروء   { id } أو { ids: [] }
POST   /api/v1/notifications/read-all         -> تعليم الكل كمقروء
DELETE /api/v1/notifications/{notification}   -> حذف إشعار

شكل عنصر الإشعار (Notification object):
{
  "id": 123,
  "title": "ريال مدريد - برشلونة",
  "body": "سجل اللاعب ... هدفا",
  "image": "https://.../image.png",
  "type": "goal",              <-- النوع الأساسي (اعتمد عليه)
  "data": { ... },             <-- مفاتيح إضافية للتوجيه
  "is_read": false,
  "created_at": "2026-10-09T10:00:00.000000Z"
}

ملاحظة مهمة:
- اعتمد على الحقل العلوي "type" (اللي جاي من عمود الداتابيز).
- ما تعتمدش على "data.type" لأنه أحياناً بيكون "reminder" كقيمة افتراضية.


==================================================
2) الأنواع الأساسية (type)
==================================================

النوع              الوصف
----------------  ------------------------------------------
goal              هدف أو هدف عكسي
events            باقي أحداث الماتش (كروت / جزاء ضائع / VAR)
match_status      تغيّر حالة الماتش (بداية/شوط/نهاية...) - تفاصيله في sub_type
reminder          تذكيرات (خط التشكيل، إشعار اليوم، 45 دقيقة) + أي حاجة غير مصنفة
announcement      إشعار مخصص من الأدمن (نص / لينك)
post              بوست جديد
team              إشعار الفريق المفضل
league            إشعار الدوري المفضل

الحاجات اللي كانت "system" اتشالت، وأي إشعار غير محدد نوعه بياخد "reminder".


==================================================
3) نوع match_status والتفاصيل (sub_type)
==================================================

النوع الأساسي دايمًا "match_status"، والتفصيل جوه البيانات في "sub_type":

sub_type          الحالة (Status code)
----------------  ------------------------------------------
match_started     1H  (بداية المباراة)
half_time         HT  (نهاية الشوط الأول)
second_half       2H  (بداية الشوط الثاني)
extra_time        ET / BT  (الوقت الإضافي / الاستراحة بينه)
penalty           P   (ركلات الجزاء)
match_ended       FT / AET / PEN  (نهاية المباراة)

أي حالة مش معروفة -> النوع "reminder".


==================================================
4) مفاتيح data حسب كل نوع (للتوجيه والتنقل)
==================================================

goal / events:
  type        = goal | events
  match_id
  fixture_id
  team_id     (الفريق صاحب الحدث)

match_status:
  type        = match_status
  sub_type    = match_started | half_time | second_half | extra_time | penalty | match_ended
  match_id
  fixture_id
  home_team_id
  away_team_id

team (الفريق المفضل):
  type        = team
  match_id
  fixture_id
  team_id     (رقم الفريق الخارجي - API id)

league (الدوري المفضل):
  type        = league
  competition_id
  league_id   (رقم الدوري الخارجي - API id)
  round
  screen      = "1"

reminder (تشكيل / يوم / 45 دقيقة):
  type        = reminder
  match_id
  fixture_id
  lineup      = "ok"   (في حالة إشعار التشكيل)

announcement:
  type        = announcement
  url         (لو إشعار لينك)  أو  match_id (لو إشعار ماتش من الأدمن)

post:
  type        = post
  post_id


==================================================
5) الـ Push (FCM) - شكل الرسالة
==================================================

كل إشعار بنبعته مرتين: مرة للإنجليزي ومرة للعربي (حسب لغة العميل).

{
  "title": "ريال مدريد - برشلونة",
  "body":  "سجل اللاعب ... هدفا",
  "image": "https://.../image.png",
  "data": {
     "match_id": "456",
     "fixture_id": "789",
     "team_id": "12",
     "type": "goal"        (قد لا يكون موجود في كل الإشعارات)
  }
}

- "data" كل قيمها نصوص (strings) عشان FCM.
- استخدم "type" للتوجيه لو موجود، وإلا اتبع المفاتيح (match_id / post_id / url).


==================================================
6) قواعد عامة للموبايل
==================================================

- اربط المستخدم بالتوكن من خلال fb_token (الباك إند بيبعت لكل توكن).
- الإشعارات بتتفلتر حسب: الفريق المفضل / الدوري المفضل / اللغة (locale).
- لتقليل الدوبليكيت: العميل بيوصله الإشعار مرة واحدة حتى لو بيمتابع الفريقين.
- عند وجود match_id -> افتح شاشة الماتش.
- عند وجود post_id -> افتح تفاصيل البوست.
- عند وجود url -> افتح المتصفح/الويب فيو.
- عند عدم وجود أي منهم -> افتح قائمة الإشعارات.


==================================================
7) ملاحظة عن البيانات القديمة
==================================================

الصفوف القديمة في جدول notifications ممكن يكون نوعها "system" أو الأنواع
القديمة للماتش (match_started / half_time / ...).

المطلوب من الباك إند: تحويلهم كالتالي:
- system                       -> reminder
- match_started/half_time/...  -> match_status + sub_type المناسب

(لو لسه ما اتعملش، ممكن الموبايل يتعامل معاهم مؤقتاً كأنهم reminder).
